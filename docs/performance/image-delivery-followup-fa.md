# بررسی گزارش تازهٔ PageSpeed و اصلاح تصویر داشبورد

تاریخ: ۲۸ اکتبر ۲۰۲۶. مبنا، دو گزارش HTML و ۱۱ تصویر PageSpeed ارسالی کاربر است. این گزارش‌ها اجرای آزمایشگاهی روی دامنهٔ تولید هستند؛ دادهٔ میدانی CrUX در آن‌ها موجود نبود. تغییرات زیر در مخزن محلی آزمایش شده‌اند و روی سرور تولید مستقر نشده‌اند.

## یافته‌ها و تصمیم‌ها

| مورد در گزارش | شاهد | اقدام |
|---|---|---|
| تصویر LCP بزرگ‌تر از نیاز | `/_next/image?w=750` همان فایل ۲۸۸۰×۱۹۰۶ و حدود ۸۳KiB را می‌فرستاد؛ PageSpeed صرفه‌جویی ۷۴ تا ۷۹KiB را تخمین زد. | برای فارسی، انگلیسی و ترکی نسخه‌های WebP با عرض ۷۵۰، ۱۲۸۰ و ۱۹۲۰ پیکسل ساخته شد. `<img srcset>` فایل مناسب را انتخاب می‌کند و preload با همان `srcset` هماهنگ است. فایل اصلی برای تصویر Open Graph حفظ شد. |
| `fetchpriority=high` در preload | تصویر از HTML اولیه قابل کشف و بدون `loading=lazy` بود؛ این مورد تنها هشدار باقی‌ماندهٔ کشف LCP است. | در آزمایش قبلی همین پروژه، افزودن اولویت اجباری به تصویر بزرگ، LCP را در سه اجرا بدتر کرد. آن را فقط برای حذف هشدار اضافه نکردیم. |
| CSS مسدودکنندهٔ رندر | دو فایل CSS جمعاً حدود ۱۰٫۷KiB انتقال دارند؛ گزارش موبایل به‌دلیل تأخیر دریافت CSS، صرفه‌جویی بالقوهٔ ۱٬۰۳۰ms نشان می‌دهد. | CSS برای چیدمان اولیه لازم است. بررسی دامنهٔ زنده، `gzip` و کش یک‌سالهٔ immutable را برای فایل هش‌دار CSS تأیید کرد؛ با این حال TTFB درخواست CSS از محل آزمایش حدود ۱٫۶s بود. بهبود تحویل از CDN/موقعیت شبکه باید در زیرساخت بررسی شود. درون‌ریزی CSS یا بارگیری غیرمسدودکننده بدون سنجش بصری، ریسک نمایش ناپایدار دارد. |
| Legacy JS حدود ۱۳KiB | گزارش به polyfillهای chunk مشترک Next اشاره می‌کند. | بدون شواهد پشتیبانی مرورگر و راه‌حل رسمی امن، تنظیم build برای حذف polyfill انجام نشد. |
| JS بلااستفاده حدود ۱۰۲KiB | حدود ۷۴KiB آن Google Tag و حدود ۲۸KiB از chunk مشترک سایت است. | Google Tag برای اندازه‌گیری تجاری حفظ و پیش‌تر با `lazyOnload` بارگیری شده است. حذف یا به‌تأخیرانداختن بیشتر tracking بدون بررسی نرخ ثبت page view انجام نشد. |
| CLS موبایل ۰٫۰۴۶ و forced reflow دسکتاپ ۷۰ms | هر دو مقدار در گزارش سبز/بدون منبع قابل انتساب بودند. | تغییر حدسی انجام نشد. CLS در آزمایش محلی پیش و پس از اصلاح تصویر صفر بود. |

## پیاده‌سازی و نتیجه

کامپوننت سروری [`DashboardImage.tsx`](../../src/components/DashboardImage.tsx) در صفحهٔ اصلی، دربارهٔ ما و جزئیات قابلیت‌ها استفاده می‌شود. نسخه‌های آماده در [`public/images/landing/responsive`](../../public/images/landing/responsive) قرار دارند. تصاویر پایین صفحه با `loading="lazy"` و تصویر LCP با `loading="eager"` و preload سازگار با `srcset` رندر می‌شود. نسبت ابعاد و متن جایگزین حفظ شدند.

| شاخص صفحهٔ اصلی فارسی، میانهٔ ۳ اجرای موبایل محلی | پیش | پس |
|---|---:|---:|
| امتیاز Performance | ۹۴ | ۹۶ |
| LCP | ۳٫۰۷۸s | ۲٫۷۸۵s |
| انتقال تصویر LCP در نمونهٔ اول | ۸۵٬۷۲۸B | ۱۵٬۷۲۲B |
| CLS | ۰ | ۰ |

هشدار «Improve image delivery» در گزارش خام محلی پس از تغییر دیگر نمایش داده نشد. مرورگر موبایل فایل ۷۵۰ پیکسلی و مرورگر دسکتاپ با عرض ۱۴۴۰، فایل ۱۲۸۰ پیکسلی را انتخاب کردند. سه اجرای پیش و پس، همگی خطای شبکه برای درخواست Google Tag داشتند؛ بنابراین اعداد TBT و امتیاز کل، معیار اثر tracking نیستند. کاهش بایت تصویر قطعی است، ولی اختلاف LCP آزمایشگاهی باید پس از استقرار با چند اجرای تولید و دادهٔ کاربران واقعی تأیید شود.

خروجی‌های قابل بازتولید: [`image-before.json`](./image-before.json)، [`image-after.json`](./image-after.json) و [`perf-measure.py`](../../scripts/perf-measure.py). تست‌های SEO، TypeScript، build و مرورگر پس از تغییر موفق بودند. مشکل CSS نیازمند بررسی TTFB و مسیر CDN/Nginx در محیط تولید است؛ هیچ پیکربندی سرور در این تغییر دستکاری نشده است.
