# گزارش ممیزی و بهینه‌سازی کارایی و SEO زیمو

تاریخ: ۲۸ اکتبر ۲۰۲۶ — نسخهٔ محلی Next.js 16.2.9 / React 19.2.7. این تغییرات در مخزن پیاده‌سازی و آزمایش شده‌اند؛ استقرار و تغییر سرور تولید انجام نشده است.

## دامنه و روش اندازه‌گیری

- خروجی `next build` همهٔ صفحه‌های بازاریابی را با SSG تولید کرد: ۵۱ URL قابل ایندکس در سه زبان و سه صفحهٔ `/about/team` که عمداً `noindex` هستند. مسیر فارسی بدون پیشوند، `/fa` با ۳۰۸، و `/en` و `/tr` مستقل باقی ماندند. داده‌های قیمت‌گذاری محلی‌اند؛ هیچ صفحهٔ عمومی به `cookies`، `headers` یا fetch زمان درخواست نیاز ندارد. برای این محتوا SSR یا ISR مزیت فعلی ندارد.
- Lighthouse 13.5.0 با Chrome 156، نمای موبایل ۴۱۲×۸۲۳، شبیه‌سازی RTT=۱۵۰ms و CPU×4 روی سرور production محلی اجرا شد. هفت مسیر نماینده سنجیده شدند؛ صفحهٔ اصلی فارسی سه بار و بقیه هرکدام یک بار. سه اجرای نهایی صفحهٔ اصلی همگی پاسخ ۲۰۰ برای Google Tag و درخواست Google Analytics را ثبت کردند. فایل‌های قابل بازتولید: [`before.json`](./before.json)، [`final.json`](./final.json)، [`scripts/perf-measure.py`](../../scripts/perf-measure.py). گزارش‌های خام Lighthouse در `/tmp/zimo-perf-before/` و `/tmp/zimo-perf-final/` همان ماشین هستند.
- نخستین اجرای مبنا هشدار timeout داشت؛ برای صفحهٔ اصلی از میانهٔ سه اجرا استفاده شده است. اندازه‌گیری‌های منفرد سایر مسیرها نوسان آزمایشگاهی دارند. INP و دادهٔ میدانی در دسترس نبودند؛ TBT جایگزین مستقیم INP نیست.

فونت فارسی از همان میزبان با WOFF2 حدود ۷۰KB، یک preload و `font-display: swap` بارگیری می‌شود. تصویر اصلی WebP حدود ۸۵KB است. تغییر فرمت، زیرمجموعه‌سازی فونت و افزودن کتابخانهٔ تازه با شواهد موجود توجیه نداشتند. تصویرهای پایین صفحه با رفتار پیش‌فرض `next/image` تنبل بارگیری می‌شوند.

## تغییرات اجراشده

- `src/app/[locale]/template.tsx` حذف شد؛ wrapper سراسری Client Component لازم نبود. [`FadeIn.tsx`](../../src/components/animations/FadeIn.tsx) و [`StaggerChildren.tsx`](../../src/components/animations/StaggerChildren.tsx) اکنون محتوای ثابت را روی سرور رندر می‌کنند. حرکت ظریف CSS در [`globals.css`](../../src/app/globals.css) برای کاربران دارای `prefers-reduced-motion` غیرفعال است.
- [`HomePricing.tsx`](../../src/components/home/HomePricing.tsx)، [`PricingSection.tsx`](../../src/components/pricing/PricingSection.tsx) و [`FeatureCards.tsx`](../../src/components/pricing/FeatureCards.tsx) دیگر برای کارت‌های ثابت Framer Motion وارد نمی‌کنند. تغییر دورهٔ پرداخت همچنان تعاملی است؛ کارت‌های قابلیت با صفحه‌کلید نیز قابل فوکوس‌اند. [`AnimatedCounter.tsx`](../../src/components/animations/AnimatedCounter.tsx) از IntersectionObserver بومی استفاده می‌کند و مقدار نهایی در HTML اولیه دیده می‌شود. `framer-motion` از `package.json` و هر دو lockfile حذف شد. تحلیل‌گر رسمی Next در build نهایی هیچ ماژول Framer Motion پیدا نکرد.
- در [`HomeHero.tsx`](../../src/components/home/HomeHero.tsx) تصویر LCP از wrapper انیمیشنی جدا و با ابعاد واقعی و `preload` تعریف شد. در [`feature/[slug]/page.tsx`](../../src/app/%5Blocale%5D/feature/%5Bslug%5D/page.tsx) ابعاد همان اسکرین‌شات اصلاح شد. آزمایش جداگانهٔ `fetchPriority="high"` هشدار Lighthouse را حذف کرد اما میانهٔ LCP را در سه اجرا حدود ۱۹۰ms بدتر کرد؛ بنابراین این آزمایش به نسخهٔ نهایی وارد نشد.
- [`layout.tsx`](../../src/app/%5Blocale%5D/layout.tsx) Google Tag را با `next/script` و `lazyOnload` بارگیری می‌کند. [`Chatwoot.tsx`](../../src/components/Chatwoot.tsx) SDK گفت‌وگو را پنج ثانیه پس از `load` اجرا می‌کند؛ تست مرورگر بارگیری دیرتر هر دو سرویس را تأیید کرد. این تصمیم نمایش دکمهٔ چت را حدود پنج ثانیه عقب می‌اندازد.
- یک prop مقایسهٔ قیمت بلااستفاده از [`pricing/page.tsx`](../../src/app/%5Blocale%5D/pricing/page.tsx) و `PricingSection` حذف شد تا دادهٔ اضافی به Client Component سریال نشود. تست‌ها در [`seo_test.py`](../../tests/seo_test.py) و [`browser-smoke.cjs`](../../tests/browser-smoke.cjs) گسترش یافتند.

## کش و شبکهٔ self-hosted

پاسخ محلی نشان داد: `/_next/static/*` دارای `public, max-age=31536000, immutable` است؛ `/_next/image` برای تصویر آزمایش‌شده `max-age=14400, must-revalidate` دارد؛ فایل‌های `public/fonts` و `public/images` اکنون `max-age=0` دارند؛ HTML ایستای Next نیز `s-maxage=31536000` برمی‌گرداند. پیکربندی Nginx/CDN تولید در این مخزن نیست و تغییر نکرد.

پیشنهاد عملی برای تنظیم لایهٔ CDN/Nginx پس از بازبینی زیرساخت:

1. `/_next/static/*`: مسیر، query و هدرهای مربوط را حفظ کنید؛ `Cache-Control: public, max-age=31536000, immutable` مناسب فایل‌های هش‌دار است.
2. HTML و پاسخ‌های RSC: کش immutable اعمال نکنید. اگر CDN HTML را کش می‌کند، کلید کش باید URL، زبان، هدرهای `RSC` و `Next-Router-State-Tree` را درست تفکیک کند و در هر deploy پاک شود. حالت محافظه‌کارانه، عبور دادن Cache-Control مبدأ و purge کامل HTML هنگام deploy است.
3. `/_next/image`: query کامل (`url`, `w`, `q`) و `Accept` را در کلید کش نگه دارید؛ TTL چهار ساعت موجود را رعایت کنید. برای فونت/تصویرهای داخل `public` فقط پس از نسخه‌دارکردن نام فایل، TTL طولانی و `immutable` اعمال کنید؛ فعلاً بازاعتبارسنجی امن‌تر است.
4. برای HTML، RSC، CSS و JS فشرده‌سازی Brotli یا gzip را در proxy فعال کنید و پاسخ‌های POST فرم‌ها و API را در کش اشتراکی قرار ندهید. پیش از تغییر، هدرهای واقعی دامنهٔ تولید و سیاست purge را بررسی کنید.

## کنترل‌های نهایی و محدودیت‌ها

- `next build` موفق؛ جدول مسیرها SSG را نشان داد. `tsc --noEmit` موفق. ESLint بدون خطا و با چهار هشدار قدیمی unused identifier تمام شد.
- ۱۱ تست HTTP/SEO موفق: ۵۱ URL قابل ایندکس، canonical و hreflang، ۳۰۸، sitemap، robots، metadata، JSON-LD، محتوای HTML اولیه، و سه صفحهٔ placeholder با `noindex`.
- ۱۵ کنترل مرورگر موفق: هیدراته‌شدن سه زبان، ناوبری و تغییر زبان، تغییر قیمت ماهانه/سالانه، FAQ، نمایش فرم‌ها، پنج صفحه در حالت بدون JavaScript، بارگیری دیرتر Chatwoot/Analytics و حالت reduced motion. ارسال واقعی فرم‌ها به API بیرونی آزمایش نشد.
- LCP هنوز بالاتر از هدف ۲٫۵ ثانیهٔ آزمایشگاهی است. تصویر اصلی در پایین بخش نخست موبایل قرار دارد و فونت/اسکریپت Analytics همچنان بخشی از مسیر بار اولیه‌اند. تغییر چیدمان یا تأخیر بیشتر در tracking بدون دادهٔ میدانی و ارزیابی تجاری توجیه ندارد. برای INP واقعی، Core Web Vitals میدانی یا RUM لازم است.
- اعداد Lighthouse محلی‌اند و جایگزین دادهٔ کاربران واقعی یا تست با Nginx/CDN تولید نیستند. سنجش‌های منفرد مسیرهای فرعی نباید به‌عنوان تضمین تغییر دقیق همان تعداد میلی‌ثانیه تعبیر شوند.
